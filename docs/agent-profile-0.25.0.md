# Рабочий профиль агента · Опора 0.25

Профиль сохраняет технические сведения об игре, чтобы Claude и Codex меньше тратили времени на повторное исследование. Он общий для проекта, сохраняется между разговорами и доступен через MCP.

## Начать в приложении

Откройте **Подключения → Рабочий профиль → Настроить через Claude**. Опора создаст отдельный разговор без задачи и передаст агенту запрос изучить проект и сохранить полезные сведения. Текущая задача не меняется, незавершённый разговор сохраняется. Если Claude занят, сначала дождитесь его ответа.

Агент наполняет профиль после чтения реальных исходников. Приложение не вызывает отдельную модель для построения профиля и не придумывает сведения само. Настройка через Claude — обычный запрос в выбранной вами сессии Claude, который расходует её токены.

## Что сохраняется

- **Точки входа:** сцены, скрипты и другие файлы, с которых удобно начинать работу над частью игры.
- **Технические особенности:** например, что конкретный экран создаётся кодом, а не собран в редакторе сцен.
- **Способы проверки:** программа, отдельные аргументы и рабочая папка. Это сохранённый рецепт, а не доказательство успешного запуска; Опора автоматически его не выполняет.

Каждая запись имеет ID, описание, область применения, автора и основание: сведения по исходникам (`source_based`) или предположение (`hypothesis`). Для записи по исходникам нужен хотя бы один файл-источник. Пути относительны папке игры; до восьми файлов-источников размером не более 1 МиБ каждый.

## Актуальность и история

Опора фиксирует SHA256 указанных файлов. При чтении профиля проверяет их снова: источник не изменился, изменился, исчез или недоступен. Запись из другой копии проекта требует повторной проверки даже при одинаковых именах файлов. Обновление такой записи заново фиксирует её источники в текущей папке.

**Неизменность файла не доказывает правильность вывода агента.** Проверка хеша подтверждает состояние источника; гипотеза остаётся гипотезой. Профиль не заменяет критерии задачи, брендбук и принятые пользователем решения. Агент должен читать актуальные исходники перед правками.

Старые версии сохраняются отдельно, с автором и причиной изменения. Их можно просмотреть в истории записи. Одинаковые сведения не создают новую версию, а повтор одного запроса не записывает изменение дважды.

В интерфейсе запись можно убрать или вернуть. Убранные записи не попадают в автоматический контекст. Запись, убранную пользователем, агент самостоятельно вернуть не может. Возврат пользователем сохраняет прежние источники и их реальное состояние: изменённый файл не становится актуальным только от нажатия «Вернуть».

## Контекст задачи

Опора подбирает до шести записей: сначала по связанным файлам и области применения, затем по названию задачи и общим техническим сведениям. Если область задачи пока не задана, точки входа могут выступать навигационными подсказками. Совпадение по словам отмечается как подсказка, а не доказательство связи.

Автоматическая часть ограничена 12 КБ, длинные записи имеют ссылку на подробное чтение. Сведения из другой копии проекта не используются в автоматическом подборе. Команда показывается в автоматическом пакете только для записи по неизменившимся исходникам; остальные рецепты можно прочитать отдельно и перепроверить. Передаются только изменившиеся разделы в уже сохранённой сессии чата.

## Через MCP

`opora_get_agent_profile` возвращает `project_id`, `profile_revision`, записи, состояние источников и страницы истории. `include_retired=true` включает убранные записи; `entry_id` выбирает одну, `history=true` включает историю, `history_offset` перелистывает её.

`opora_update_agent_profile` поддерживает `upsert` и `retire`. Нужны текущая `profile_revision`, `project_id`, автор, причина и `request_id`. Ревизия профиля независима от общих настроек игры, поэтому правка другого поля проекта не заставляет повторять профильный запрос. При конкурентном изменении агент перечитывает профиль вместо перезаписи чужих данных.

Пример записи:

```json
{
  "id": "shop-entry",
  "kind": "entry_point",
  "title": "Экран магазина",
  "body": "Экран создаётся кодом в ui/shop.gd; перед правками прочитать этот скрипт.",
  "certainty": "source_based",
  "sources": ["ui/shop.gd"],
  "scope_paths": ["ui"]
}
```

Технические сведения сохраняются без отдельных подтверждений. Профиль не меняет разрешения, правила и брендбук; рецепты проверок сохраняются как данные. После обновления уже запущенному внешнему MCP-клиенту нужна новая сессия для получения новых инструментов. Кнопка настройки во встроенном чате создаёт свежую сессию сама.

## Хранение и проверки

Текущий профиль: `.opora/agent-profile.json`. Предыдущие версии: `.opora/agent-profile-history/`. Профиль ограничен 100 записями и 512 КиБ; история не обрезается при замене записи. Агент работает через MCP, а не редактирует эти файлы напрямую. Запись атомарна и защищена от параллельных изменений.

Проверены сохранение без изменения пользовательских требований, повторные запросы, отсутствие лишних версий, устаревшие/удалённые/скопированные источники, история, небезопасные пути, управление пользователем и отсутствие автоматического выполнения рецептов. Тесты интерфейса используют реальный Electron и локальный тестовый CLI без вызова платной модели.
