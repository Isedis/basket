# Восстановление запуска 0.12.1

До 0.12.1 загрузка `ui/index.html` ожидала `TerminalClient.connect()`.
Повреждённая запись брокера прерывала запуск, а сервер без ответа задерживал
интерфейс. Переустановка приложения сохраняет эту запись в профиле пользователя.
По скриншоту нельзя установить, был ли именно этот сбой на компьютере пользователя.

Теперь подключение терминала выполняется отдельно от загрузки интерфейса.
Подтверждение подключения ограничено четырьмя секундами, неудачный сокет закрывается.
Восстановление проекта ждёт ограниченное подключение, чтобы сохранить правильный
проект активного терминала. Настройка прокси также не блокирует загрузку окна.

В Windows отключено аппаратное ускорение: рабочему месту с DOM и терминалом
не требуется GPU. Это дополнительная мера совместимости, а не подтверждённый
диагноз драйвера пользователя. Журнал `%APPDATA%/opora/startup.log` фиксирует
версию, этапы и ошибки. При ошибке загрузки или завершении процесса интерфейса
открывается экран диагностики с копированием журнала и повторным запуском.
Пустое окно и экран диагностики закрываются без ожидания обработчика сохранения
из отсутствующего интерфейса.

В малом ZIP есть `REPAIR-OPORA.cmd`. Его запускают рядом с прежним
`START-OPORA.cmd` либо `Opora.exe`. Сначала он запрашивает обычное закрытие;
если через десять секунд окно не отвечает, завершает только GUI с точным
совпадением пути. Он не завершает дерево процессов, отдельный брокер Claude
или MCP. Для старых версий с вложенным терминалом сохраняется проверка
дочерней сессии. Обычный `UPDATE-OPORA.cmd` не использует принудительное
завершение. Режим восстановления разрешает переустановить ту же версию.
Папки игры `.opora` и профиль приложения не удаляются.

`scripts/startup-smoke.cjs` на Windows запускает именно `Opora.exe` из
четырёх опубликованных частей ZIP, без замены ASAR или точки входа.
Проверяются сохранённые пометки, повреждённая запись брокера, сервер без
ответа, программная отрисовка и экран ошибки загрузки. Профиль задаётся
стандартным `--user-data-dir`, поскольку замена переменной `APPDATA`
не меняет Windows Known Folder, используемую Electron.

Отдельный сценарий `OPORA_TEST_UPDATE_MODE=repair` создаёт окно, которое
отказывается закрываться, запускает настоящий CMD и .NET-помощник,
проверяет запуск новой версии и сохранение действующей MCP-сессии.
Машиночитаемый результат Windows сохранён рядом в файле
`windows-update-validation-0.12.1.json`.
