# Обновление 0.14: подтверждение отрисовки и штатный перезапуск

Причина пустого окна воспроизведена на опубликованных 0.13.0 и 0.13.1.
`windowsHide: true` у запуска GUI передаёт Windows флаг скрытого окна.
Это не настройка только консоли: Chromium выполнял JavaScript, отправлял
`workspace-ready`, но видимая область окна оставалась пустой. Старое
подтверждение ошибочно считало такой запуск успешным.

На тех же бинарных файлах проверены варианты запуска: с `windowsHide` в
снимке окна обнаружен один цвет, без него — 92 цвета. Наличие переменных
задания обновления не меняет результат. Исходный интерфейс перед обновлением
также имел 92 цвета.

Новый механизм использует протокол 3:

1. Приложение скачивает пакет и проверяет SHA256. Новая версия готовится в
   отдельной папке; неизменённый Electron используется локально.
2. Фоновый наблюдатель повторно проверяет подготовленные файлы и получает
   исключительную блокировку задания. Он не запускает новое окно.
3. После сохранения данных и отсоединения от отдельного брокера Claude
   приложение переключает указатель и вызывает `app.relaunch`. При ошибке
   подготовки перезапуска указатель сразу восстанавливается.
4. Новое приложение сообщает PID с токеном задания. После загрузки проекта
   проверяются видимость окна и непустой отрисованный кадр через `capturePage`.
   Только после этого записывается подтверждение `painted: true`.
5. Наблюдатель подтверждает PID, версию, путь и изображение. При ошибке или
   тайм-ауте он завершает только GUI этого задания, восстанавливает указатель
   и открывает предыдущую версию без флага скрытого окна. Брокер Claude,
   внешние MCP и папка игры не удаляются.

Координация новых GUI использует собственный локальный канал, а Chromium —
отдельный `sessionData`. Поэтому старое зависшее окно 0.13 с его блокировкой
единственного экземпляра и кэшем не блокирует готовую новую сборку.

Удалены прежние PowerShell-установщики, старый worker запуска GUI, мигратор,
Windows-контроллер и ручные START/UPDATE/REPAIR-пакеты. От старого протокола
оставлено только чтение задания и подтверждение отрисовки для однократного
перехода с установленной 0.13; старый установщик не входит в новую программу.

Windows CI проверяет готовый `Opora.exe` с обычным профилем: штатное обновление
0.14.0 → тестовая 0.14.1 (меняется только версия в ASAR), переход с опубликованной
0.13.0, сохранение заметок, работающую сессию PTY/MCP и откат при падении нового
GUI. Дополнительно проверяется снимок видимого рабочего стола после обновления,
чтобы JS-подтверждение больше не скрывало отсутствие изображения.

Результат и снимки: ветка `opora-windows-validation`, файлы `windows-update.json`,
`opora-release.png` и `opora-oldbase.png`. Снимок проверенного выпуска и отчёт
сохранены рядом с этой инструкцией.
