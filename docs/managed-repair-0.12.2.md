# Восстановление после предыдущих обновлений — 0.12.2

Ошибка `Запущена предыдущая копия Опоры. Откройте текущую версию.`
возникала до подготовки обновления и закрытия GUI. CMD запускает мигратор
через исходный `Opora.exe`, а указатель установки после обновления ведёт в
`runtime/<id>/v/<version>`. Мигратор передавал исходный executable в
`prepareInstall`, который правильно запрещает обновлять неактивную копию.

Мигратор теперь передаёт `current.directory/Opora.exe` из проверенного
указателя. Исходный executable остаётся загрузчиком CMD и нового стартера.
Проверка неактивной копии в обычном обновлении не ослаблена, откат сохраняет
путь предыдущей активной версии. Папка игры и `.opora` не меняются.

Предыдущий тест восстановления удалял реестр версий перед запуском CMD,
моделируя первый переход со старого приложения. Поэтому он не проверял
расхождение путей после уже установленного обновления.

Теперь Windows-сценарий ремонта сохраняет реестр, создаёт отдельную
предыдущую активную версию, запускает её GUI, блокирует закрытие окна и
вызывает `REPAIR-OPORA.cmd` через исходный executable. Проверяются новая
версия, сохранение старой активной копии, пометки, MCP и `START-OPORA.cmd`.
Дополнительный сценарий проверяет обычный `UPDATE-OPORA.cmd` в такой установке.
Unit-проверка отдельно подтверждает отказ для исходной неактивной копии и
успешную подготовку через текущую.

Результаты Windows: `windows-update-validation-0.12.2.json`.
