# Опора 0.2 — память игры, автоматический брендбук и обновления

Локальное приложение для Windows 10/11 x64. Паспорт игры Godot, брендбук, визуальные эталоны, задачи и общие инструкции для помощников. Программировать и вводить API-ключи не нужно.

## Скачать и запустить

1. **[Скачать готовую «Опору» для Windows](https://github.com/Isedis/basket/archive/refs/heads/opora.zip)** — около 159 МБ. Это ZIP всей ветки, в нём уже есть готовая сборка.
2. **Полностью распакуйте ZIP** в обычную папку. Не запускайте файлы прямо внутри архива.
3. В распакованной папке дважды щёлкните **`START-OPORA.cmd`**. Он проверит контрольные суммы, соберёт и распакует готовое приложение, затем откроет его. Node.js и сборка из исходников не нужны. Дождитесь завершения: первый запуск может занять минуту.
4. В приложении нажмите **Подключить проект** и выберите папку своей игры с `project.godot`.

Если у вас версия 0.1, один раз скачайте новую сборку вручную. Данные подключённой игры сохранятся в её папке `.opora`. Следующие версии можно будет получать из программы.

## Автоматический брендбук

У нового проекта черновик создаётся сразу после подключения папки: палитра из сцен, тем и скриптов, файлы шрифтов, размеры текста, параметры оформления и до шести изображений-кандидатов. Показываются пути и строки источников.

В существующем проекте откройте **Визуальный стиль → Собрать брендбук из проекта**. При повторном анализе выбирайте поля для замены: ваши правки по умолчанию сохраняются. Картинки добавляются кандидатами, утверждённые образцы не теряют статус.

Это локальный статический анализ, без отправки игры в нейросеть. Частота цвета в файлах не определяет его роль. Художественное настроение не угадывается, динамический вид запущенных экранов не анализируется. Если явных цветов нет, предлагаются приблизительные цвета выбранных изображений.

## Обновления прямо из программы

**Обновления → Проверить обновления → Скачать обновление → Установить и перезапустить.**

Программа загружает описание версии из этой ветки GitHub, а части архива — из указанного неизменяемого коммита. Проверяет размеры и SHA256 каждой части и всего ZIP. Повреждённый архив не устанавливается. Перед заменой сохраняются данные проекта, прежняя папка приложения переносится в резервную копию. При ошибке замены установщик пытается восстановить её.

Установка предназначена для Windows-сборки в доступной пользователю папке. В браузерном демо и при запуске из исходников она недоступна. Новая версия появляется, когда автор опубликует её в канале; приложение само не создаёт релизы.

После первого запуска можно открывать `Opora-App/Opora-win32-x64/Opora.exe` напрямую. Все остальные файлы рядом с exe нужно сохранить.

Быстро посмотреть интерфейс без приложения: откройте `Opora-demo.html` из скачанного ZIP в браузере. Это только демо, оно не подключает папку игры.

## С чего начать

Запишите пять самых частых замечаний в «Чтобы не повторять снова». Добавьте брендбук и изображения, когда будете готовы. Выберите одну небольшую задачу и в разделе «Контекст для ИИ» обновите файлы проекта, затем скопируйте запрос для Claude Code или Codex.

Opora сохраняет существующие `AGENTS.md` и `CLAUDE.md`, добавляя только свой блок. Перед синхронизацией создаётся резервная копия. Приложение не генерирует графику и пока не оценивает соответствие стилю автоматически.

Полная инструкция и результаты аудита: [OPORA.md](OPORA.md).

## О сборке

Интерфейс, автоматический брендбук, файловые операции, нативный буфер обмена, проверка версий и восстановление проекта проверены в Electron под Linux. Загрузка и проверка обновлений тестируются отдельно. Запуск exe, `.cmd` и замена запущенного приложения непосредственно в Windows здесь не проверены. Бинарник не подписан сертификатом издателя.

Windows-архив хранится частями в `distribution/windows/`, поскольку GitHub не принимает отдельные Git-файлы больше 100 МБ. Запускатель проверяет SHA256 каждой части и всего собранного ZIP. Отдельно скачивать части не требуется — они уже входят в ZIP ветки.
