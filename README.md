# Опора 0.17.0 — рабочее место для разработки игры

**[Скачать готовую Опору для Windows](https://github.com/Isedis/basket/releases/download/v0.17.0/Opora-Windows.zip)**

**Автоматическая работа — 0.17.** Выберите задачу и нажмите «Выполнить в Claude». Опора сама подготовит контекст, затем будет передавать только изменившиеся разделы. После потери истории или сжатия сессии возвращается полный пакет. После ответа сохраняются сводка, связь с исходной задачей и наблюдаемые изменения индексируемого кода/сцен/ресурсов; параллельные правки могут попасть в список. Принятие результата, завершение задачи и утверждение стиля остаются у пользователя.

Если после ответа изменились исходники, Опора автоматически проверяет импорт проекта в Godot и разбирает изменённые GDScript через `--check-only`. Godot ищется в PATH; если его нет, раскройте автоматическую сводку и один раз нажмите «Указать Godot». Проверка ограничена 45 секундами и 20 изменёнными GDScript за ответ; покрытие и пропуски записываются в отчёт. Ошибки передаются в следующий запрос этой задачи; «Исправить ошибки» запускает исправление без копирования логов. Проверка не подтверждает игровой процесс, визуал или сборку C#. Снимки и визуальное принятие остаются отдельными действиями.


Claude открывается в нижней панели: чат, история разговоров и отдельное поле ввода. Тяните верхнюю границу для изменения высоты; размер текста и скрытие истории сохраняются. «Контекст Опоры» прикладывает активную задачу, правила, брендбук и связанные замечания. Действия, требующие разрешения, подтверждаются в чате. Вкладка «Терминал» сохраняет обычный Claude Code. Используются ваша установка CLI и её авторизация.


Распакуйте архив в новую папку и запустите **`Opora.exe`** из папки `Opora-win32-x64`.
Опора откроет последний проект, если сохранился путь к нему. Иначе нажмите «Открыть проект» и выберите папку игры с `project.godot`. Пометки, задачи и брендбук сохраняются в папке игры `.opora`.

## Claude Code внутри Опоры — 0.11

Выберите игру и нажмите **«>_ Claude»** в верхней панели или **«Агенты → Открыть в Опоре»**. Откроется интерактивный терминал установленного Claude Code: обычный вход, диалог и запросы разрешений. MCP этой игры настраивается автоматически; первый запрос к Опоре агенту подсказывает инструкция сессии. Подтверждение серверов остаётся в Claude.

**«Вставить задачу»** добавляет запрос по текущей задаче в строку ввода; отправьте его сами клавишей Enter. Панель можно скрыть или развернуть, сессия продолжает работать. **«Продолжить последнюю»** использует последнюю историю Claude в папке этой игры. Копирование и вставка: **Ctrl+Shift+C / V**. Для смены игры завершите сессию; обычное закрытие приложения предложит завершить Claude. Обновление сохраняет работающую сессию.

Если CLI не найден, выберите **«Указать Claude»** и укажите `claude.exe` или стандартный npm-файл `claude.cmd` (для него нужен Node.js в PATH). Устанавливается Claude Code отдельно, используются его существующие учётные данные. Опора не добавляет API-ключей и не отключает разрешения агента. Содержимое терминала Опора не записывает; история хранится самим Claude Code.

Проверены настоящий PTY под Electron, клавиатура, Unicode, сохранение сессии при смене разделов, остановка и продолжение на тестовом интерактивном CLI. Сеанс модели с реальным аккаунтом и Windows ConPTY в Linux не запускались. В Windows-сборке поставляются официальные N-API-модули node-pty 1.1.0 и xterm.js 6.0.0. Они входят в малое обновление; скачивать Electron заново не требуется.

## Обновления одной кнопкой — 0.12

Откройте **«Обновления → Проверить и обновить»**. Опора сама сохранит данные, скачает и проверит пакет, подготовит новую версию и перезапустит окно. **Закрывать Claude и терминалы MCP не нужно.** Встроенный Claude работает в отдельном локальном процессе и сохраняет разговор при обновлении окна.

Новая версия устанавливается отдельно от работающей. Действующие MCP-сессии продолжают использовать свою копию; следующая сессия, настроенная новым подключением, выбирает текущую версию. Если новый интерфейс не запустился, указатель возвращается к предыдущей версии и она открывается снова. При повреждении Electron автоматически выбирается полный пакет восстановления; обычное обновление остаётся около 6,4 МБ. Неизменённые файлы Electron используют жёсткие ссылки, где это возможно, или копируются локально.

**Переход со старой версии:** [скачайте готовую сборку](https://github.com/Isedis/basket/releases/download/v0.17.0/Opora-Windows.zip), распакуйте в новую папку и запустите `Opora.exe`. Последняя игра откроется автоматически, если сохранился путь к ней.

Проверено **на Windows** в [GitHub Actions](https://github.com/Isedis/basket/actions/runs/42173703348): кнопка с работающим Claude PTY и MCP, сохранение PID терминала, локальное использование Electron, откат при неудачном запуске. Проверяются также пути с русскими буквами, пробелами, скобками, `%`, `!`, `&` и апострофом. Реальные платные запросы Claude в тестах не отправляются.

## Единый контекст задачи — 0.10

На рабочем столе нажмите **«Контекст задачи»**: выбранная задача, связанные замечания, действующие решения и предупреждения теперь собраны вместе. **«Скопировать запрос»** тоже передаёт этот пакет. Агент начинает с **`opora_get_work_context`**, проверяет папку и получает основные данные за один запрос; изображения и подробности остаются доступными отдельными инструментами.

Пакет содержит версии контекста, замечаний, карты и исходников. При повторном чтении с `known_revision` возвращается короткий ответ, если пакет не изменился и сохранился у агента. После потери истории параметр нужно убрать. Длинные поля явно сокращаются со ссылкой на **`opora_read_project_field`**; задача и брендбук доступны постранично. Ответ записи проекта по умолчанию — короткое подтверждение; `include_state=true` возвращает полное состояние.

Исправлены ошибки аудита: большая дельта заменяется более коротким полным контекстом; ручная правка снимает утверждение брендбука; все пути записи проекта соблюдают 2 МиБ; пути результатов из Windows CMD принимаются с обратными слешами. Карта показывает количество символов, страницы и ссылки на глобальные классы.

В замечаниях выбирается область действия: **область снимка / сцена / весь проект**. Новое решение «сохранить» может явно заменить предыдущее после принятия пользователем. Старые попытки автоматически выносятся в проверяемые архивы, остаются доступными для сравнения и истории; лимита 30 попыток больше нет. Закрытые обсуждения можно скрывать и восстанавливать. Изменения других замечаний не мешают отправке результата, если агент передаёт актуальные `note_revisions` затронутых записей.

Отчёты и вложения записывают версию исходников при прикреплении. Изменение кода и изменение контекста отображаются отдельно; совпадение результата с оригиналом отмечается. Это помогает проверить актуальность, но не доказывает запуск игры. В разделе «Агенты» можно отключить запись этой игры, сохранив остальные серверы; запущенную сессию нужно перезапустить.

## Замечания на снимках — 0.9

Откройте **«Замечания»** или нажмите **Ctrl+7**. Добавьте снимок из файла либо сделайте **Win+Shift+S** и нажмите **«Из буфера»** (также работает вставка изображения вне текстовых полей). PNG/JPG/WebP из файла сохраняются локально как PNG.

1. Выделите область мышью или нажмите «Весь экран».
2. Выберите **«Исправить»** или **«Нравится — сохранить»**, напишите комментарий и сохраните. Сцену/файл можно указать вручную.
3. Нажмите **«Для агента»**: запрос содержит ссылку на снимок, область и замечание. **«В задачи»** создаёт связанную задачу без повторного добавления незавершённой записи.
4. Подключённый MCP-агент читает замечания и исходный снимок с координатами, затем прикладывает новый PNG из папки игры. Результат появляется рядом с оригиналом; его также можно добавить кнопкой **«+ Результат из файла»**.
5. Выберите последнюю версию и нажмите **«Принять»** либо укажите причину и нажмите **«Вернуть»**. Предыдущие результаты и решения остаются в истории.

Агент не принимает результат за вас. Принятые отметки «сохранить» доступны в следующих сессиях; утверждение брендбука и завершение задачи остаются отдельными действиями. Совпадающий снимок и одинаковое замечание в той же области повторно не создаются. Сходные по смыслу формулировки автоматически не объединяются.

После обновления перезапустите MCP-сессию: доступны **`opora_list_feedback`**, **`opora_get_feedback_image`**, **`opora_submit_feedback_result`**. Для ручной передачи агенту нужен доступ к папке игры со снимками.

## Карта проекта — 0.8

Откройте **«Карта проекта»** в меню или нажмите **Ctrl+6**. Карта автоматически строится при открытии раздела. Слева — поиск по пути/классу и фильтры файлов, справа — связи выбранного файла: **где используется → файл → на что ссылается**. Нажмите карточку, чтобы перейти к соседнему файлу. «Главная сцена» открывает точку входа, «Обновить» перечитывает состояние папки, «Для агента» копирует выбранный фрагмент с номерами строк.

Через MCP агент получает ту же карту инструментом **`opora_get_project_map`**. Можно попросить: «Прочитай карту Опоры, найди сцену меню и её зависимости, затем предложи изменения». Для появления инструмента после обновления перезапустите MCP-сессию. Неизменённые файлы повторно не разбираются. Динамические загрузки и неразрешённые UID отмечаются; отсутствие входящих ссылок не означает, что файл можно удалить.

## Заполнить Опору через агента

1. Обновите Опору до **0.12.0** и перезапустите MCP-сессию Claude Code или Codex.
2. На **Рабочем столе → Заполнить через агента** скопируйте запрос для всей игры. Для одного стиля та же кнопка есть в разделе «Брендбук».
3. Вставьте запрос агенту. Он изучит файлы игры и вызовет **`opora_update_project`**: паспорт, цель, постоянные правила, брендбук, задачи с критериями и изображения-кандидаты.

Агент записывает направление, палитру, шрифты с размерами и ограничения прямо в Опору. Результат всегда черновик, предыдущие настройки сохраняются в резервной копии. Изображения и утверждение стиля остаются под вашим контролем. Открытое окно подхватывает изменения примерно за две секунды; при параллельных правках одного поля показывает обе версии. Инструмент одного брендбука не меняет задачи и правила; общий инструмент умеет их заполнять, сохраняя пропущенные поля и существующие записи. Завершение задач подтверждаете вы.

Можно попросить напрямую: «Изучи мою игру и заполни Опору через opora_update_project. Сохрани существующие решения, добавь задачи с критериями, стиль оставь черновиком».

## Меньше повторного чтения агентом

`opora_get_context` принимает `known_revision`, когда предыдущий контекст ещё есть в чате. При отсутствии изменений ответ короткий; при изменениях возвращаются только заменённые поля. Смена выбранной задачи включает её критерии. Опора хранит последние 8 версий в MCP-процессе. При неизвестной версии, перезапуске сервера или слишком большом изменении возвращается полный контекст. После сжатия чата агент должен опустить `known_revision` и перечитать всё. Проверки актуальности и доступные инструменты сохраняются; экономия зависит от частоты изменений и размера вашего контекста.

## Терминальный интерфейс 0.6

Плоские панели с рамками, инверсное выделение разделов, маршрут проекта в шапке и постоянная строка состояния. Прокручивается рабочая область, навигация и статусы остаются на месте. Выбранная задача видна в боковой панели. [Снимок рабочего стола](docs/terminal-workspace.png).

**Ctrl+K** открывает меню команд. Введите название действия, выберите его стрелками и нажмите Enter; Escape закрывает меню. Доступны переходы между разделами, новая задача, копирование запроса, разбор брендбука, открытие и сохранение проекта, обновления и справка. Поддерживаются русские названия и английские слова, например `/tasks` и `/save`. Из открытого диалога задачи команды не вызываются, чтобы сохранить введённый текст.

## Оформление

Оформление по брендбуку Isidacorp: чёрный фон, светлый текст `#FFF2CC`, красный акцент `#FF0000` и локальный JetBrains Mono. На рабочем столе — текущая задача, критерии готовности, очередь и постоянные правила. Поля брендбука и разбор стоят рядом; источники анализа и подробные пояснения свёрнуты. Палитра самой игры остаётся её собственным решением.

`Ctrl+K` — команды, `Ctrl+1…5` — разделы, `Ctrl+N` — новая задача, `Ctrl+S` — сохранить, `Ctrl+Enter` — сохранить задачу в диалоге или скопировать запрос в разделе «Контекст», `F1` — справка.

## Разбор брендбука с подсказками

Откройте **Брендбук → Разбор**. Проверяются 9 пунктов: направление, HEX-цвета, роли палитры, заявленные пары текста и фона, шрифты, типографика, доступные утверждённые образцы, ограничения и статус утверждения.

Каждое замечание показывает причину и предложение. Кнопка **К полю →** переводит к нужной настройке; **Добавить задачу** создаёт задачу без дубликата. Можно скопировать весь разбор агенту. У подключённого агента тот же результат доступен через `opora_review_brandbook`; после обновления перезапустите его MCP-сессию.

Для проверки контраста подпишите по одному цвету текста и фона либо задайте явную пару:

```text
Основной текст: #FFFFFF на #151E21
Крупный текст: #DDDDDD на #333333
```

Ориентир — 4.5:1 для обычного текста и 3:1 для явно помеченного крупного. Размер и отображение в Godot проверяются отдельно. Случайные сочетания палитры не объявляются ошибками; полупрозрачные пары без итоговой подложки не получают выдуманный коэффициент. Предложение замены сначала выбирается из существующей палитры.

Число «N / 9» показывает полноту проверяемых правил, а не художественное качество. Приложение не анализирует красоту изображений, реальные экраны или интересность игры. Файлы образцов проверяются автоматически при открытии раздела и по кнопке **Проверить →**; правила не меняются сами.

## Подключить агента напрямую — MCP

1. Подключите папку своей игры. Откройте **Агенты**.
2. У Claude Code или Codex нажмите **Настроить подключение → Добавить подключение**.
3. Перезапустите терминальную сессию агента **в папке этой игры**. Если клиент запросит разрешение на MCP-сервер, подтвердите его в клиенте.
4. Попросите агента прочитать Опору и выполнить выбранную задачу. На странице есть кнопка копирования первого запроса.

Локальный stdio-процесс не открывает порт и работает при закрытом окне Опоры. Node.js отдельно не нужен — используется runtime приложения. Сам Claude Code или Codex должен быть уже установлен и авторизован как обычно; отдельный API-ключ для Опоры не требуется.

Для Claude дополняется `.mcp.json` выбранного проекта. Для Codex добавляется сервер с отдельным именем в пользовательский `config.toml` (`CODEX_HOME`, если задан, иначе `~/.codex`). Другие серверы и настройки сохраняются, перед изменением создаётся резервная копия. «Настроено» означает сохранённую конфигурацию, а не подтверждённое соединение клиента.

Агент получает контекст, брендбук, его разбор, задачи и изображения через 16 MCP-инструментов. Папка закреплена при запуске; запрос с чужим `project_id` отклоняется. Если пользователь изменил контекст, отчёт со старой `revision` отклоняется до перечитывания данных. Агент должен проверить, что путь сервера совпадает с игрой, над которой он работает.

Отчёты появляются в **Агенты**. Проверки заявлены самим агентом: Опора не считает их независимым доказательством и не переводит задачу в «готово». Отчёты сохраняются отдельно от настроек и не затирают правки интерфейса.

## Автоматический брендбук

У нового проекта черновик создаётся сразу после подключения папки: палитра из сцен, тем и скриптов, файлы шрифтов, размеры текста, параметры оформления и до шести изображений-кандидатов. Показываются пути и строки источников.

В существующем проекте откройте **Брендбук → Собрать из проекта**. При повторном анализе выбирайте поля для замены: ваши правки по умолчанию сохраняются. Картинки добавляются кандидатами, утверждённые образцы не теряют статус.

Это локальный статический анализ, без отправки игры в нейросеть. Частота цвета в файлах не определяет его роль. Художественное настроение не угадывается, динамический вид запущенных экранов не анализируется. Если явных цветов нет, предлагаются приблизительные цвета выбранных изображений.

## Обновления прямо из программы

**Обновления → Проверить и обновить.** Данные сохраняются автоматически, терминал Claude и MCP продолжают работу. Перед перезапуском проверяются архив и подготовленная версия; новая GUI подтверждает готовность интерфейса. При неудачном запуске открывается предыдущая версия. Путь и журналы доступны в «Папка и диагностика».

Обычный пакет содержит только приложение. Если установленный Electron повреждён, Опора сама загрузит полную сборку. Интернет используется после нажатия кнопки. Установка доступна в Windows-сборке; браузерное демо версии не устанавливает.

После перехода со старой версии запускайте **START-OPORA.cmd**: он выбирает текущую копию. У exe версий начиная с 0.12 тоже есть перенаправление на текущую версию. Сохраняйте исходную папку установки — она содержит стабильный запуск и runtime действующих MCP-сессий.

Быстро посмотреть интерфейс без приложения: откройте `Opora-demo.html` из скачанного ZIP в браузере. Это только демо, оно не подключает папку игры.

## С чего начать

Запишите пять самых частых замечаний в «Постоянные правила». Добавьте брендбук и изображения, когда будете готовы. Выберите одну небольшую задачу и в разделе «Контекст» обновите файлы проекта, затем скопируйте запрос для Claude Code или Codex.

Opora сохраняет существующие `AGENTS.md` и `CLAUDE.md`, добавляя только свой блок. Перед синхронизацией создаётся резервная копия. Приложение не генерирует графику и пока не оценивает соответствие стилю автоматически.

Полная инструкция и результаты аудита: [OPORA.md](OPORA.md).

## О сборке

Интерфейс и 95 Node-тестов проверяются локально. GitHub Actions отдельно запускает настоящие Windows GUI, ConPTY, открытый MCP, обновление по кнопке, откат и CMD-переход. Результат проверенного прогона указан выше. Тесты используют локальный интерактивный CLI вместо аккаунта Claude.

Windows-архив хранится частями в `distribution/windows/`, поскольку GitHub не принимает отдельные Git-файлы больше 100 МБ. Запускатель проверяет SHA256 каждой части и всего собранного ZIP. Отдельно скачивать части не требуется — они уже входят в ZIP ветки.
