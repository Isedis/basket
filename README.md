# Опора 0.5 — рабочее место для разработки игры с агентами

Локальное приложение для Windows 10/11 x64. Паспорт игры Godot, брендбук, визуальные эталоны, задачи и общие инструкции для помощников. Программировать и вводить API-ключи не нужно.

## Скачать и запустить

1. **[Скачать готовую «Опору» для Windows](https://github.com/Isedis/basket/archive/refs/heads/opora.zip)** — около 162 МБ. Это ZIP всей ветки, в нём уже есть готовая сборка.
2. **Полностью распакуйте ZIP** в обычную папку. Не запускайте файлы прямо внутри архива.
3. В распакованной папке дважды щёлкните **`START-OPORA.cmd`**. Он проверит контрольные суммы, соберёт и распакует готовое приложение, затем откроет его. Node.js и сборка из исходников не нужны. Дождитесь завершения: первый запуск может занять минуту.
4. В приложении нажмите **Открыть проект** и выберите папку своей игры с `project.godot`.

В версии 0.2 и новее есть кнопка «Обновления» для перехода на 0.5. Если у вас версия 0.1, скачайте новую сборку вручную. Перед ручным запуском закройте старую Опору. Данные подключённой игры сохраняются в её папке `.opora`.

## Если при запуске «Отказано в доступе к Opora.exe»

Прежний запускатель каждый раз распаковывал архив поверх приложения. Открытая Опора или её MCP-процесс могут блокировать замену `exe`.

1. Закройте Опору и терминальные сессии Claude/Codex с её MCP.
2. [Скачайте маленький архив с исправленным запускателем](https://github.com/Isedis/basket/raw/refs/heads/opora/distribution/Opora-launcher-fix.zip). Извлеките из него `START-OPORA.cmd` и замените им файл в распакованной папке `basket-opora`, рядом с `distribution`.
3. Запустите его обычным двойным щелчком. Заново скачивать все части приложения не требуется.

Исправленный запускатель использует отдельную временную папку, сохраняет прежнюю копию при замене и откатывает замену при ошибке запуска. Следующий запуск готовой копии пропускает сборку и распаковку. Более новая версия, установленная из программы, не заменяется старой из ZIP.

При повторной ошибке рядом с запускателем появляется `OPORA-LAUNCH.log` с этапом и причиной. Если отказ возникает и в новой папке, проверьте журнал защиты Windows: точную причину блокировки нельзя определить только по этому сообщению. Отключать защиту или запускать от администратора не требуется. Старые папки `Opora-App.backup-*` можно убрать после проверки новой копии; папки игр запускатель не заменяет.

## Интерфейс 0.5

Оформление по брендбуку Isidacorp: чёрный фон, светлый текст `#FFF2CC`, красный акцент `#FF0000` и локальный JetBrains Mono. На рабочем столе — текущая задача, критерии готовности, очередь и постоянные правила. Поля брендбука и разбор стоят рядом; источники анализа и подробные пояснения свёрнуты. Палитра самой игры остаётся её собственным решением.

`Ctrl+1…5` — разделы, `Ctrl+N` — новая задача, `Ctrl+S` — сохранить, `Ctrl+Enter` — сохранить задачу в диалоге или скопировать запрос в разделе «Контекст», `F1` — справка.

## Разбор брендбука с подсказками

Откройте **Брендбук → Разбор**. Проверяются 9 пунктов: направление, HEX-цвета, роли палитры, заявленные пары текста и фона, шрифты, типографика, доступные утверждённые образцы, ограничения и статус утверждения.

Каждое замечание показывает причину и предложение. Кнопка **К полю →** переводит к нужной настройке; **Добавить задачу** создаёт задачу без дубликата. Можно скопировать весь разбор агенту. У подключённого агента тот же результат доступен через `opora_review_brandbook`; после обновления перезапустите его MCP-сессию.

Для проверки контраста подпишите по одному цвету текста и фона либо задайте явную пару:

```text
Основной текст: #FFFFFF на #151E21
Крупный текст: #DDDDDD на #333333
```

Ориентир — 4.5:1 для обычного текста и 3:1 для явно помеченного крупного. Размер и отображение в Godot проверяются отдельно. Случайные сочетания палитры не объявляются ошибками; полупрозрачные пары без итоговой подложки не получают выдуманный коэффициент. Предложение замены сначала выбирается из существующей палитры.

Число «N / 9» показывает полноту проверяемых правил, а не художественное качество. Приложение не анализирует красоту изображений, реальные экраны или интересность игры. Файлы образцов проверяются автоматически при открытии раздела и по кнопке **Проверить →**; правила не меняются сами.

## Подключить агента напрямую — MCP

1. Подключите папку своей игры. Откройте **Агенты**.
2. У Claude Code или Codex нажмите **Настроить подключение → Добавить подключение**.
3. Перезапустите терминальную сессию агента **в папке этой игры**. Если клиент запросит разрешение на MCP-сервер, подтвердите его в клиенте.
4. Попросите агента прочитать Опору и выполнить выбранную задачу. На странице есть кнопка копирования первого запроса.

Локальный stdio-процесс не открывает порт и работает при закрытом окне Опоры. Node.js отдельно не нужен — используется runtime приложения. Сам Claude Code или Codex должен быть уже установлен и авторизован как обычно; отдельный API-ключ для Опоры не требуется.

Для Claude дополняется `.mcp.json` выбранного проекта. Для Codex добавляется сервер с отдельным именем в пользовательский `config.toml` (`CODEX_HOME`, если задан, иначе `~/.codex`). Другие серверы и настройки сохраняются, перед изменением создаётся резервная копия. «Настроено» означает сохранённую конфигурацию, а не подтверждённое соединение клиента.

Агент получает контекст, брендбук, его разбор, задачи и изображения через 8 MCP-инструментов. Папка закреплена при запуске; запрос с чужим `project_id` отклоняется. Если пользователь изменил контекст, отчёт со старой `revision` отклоняется до перечитывания данных. Агент должен проверить, что путь сервера совпадает с игрой, над которой он работает.

Отчёты появляются в **Агенты**. Проверки заявлены самим агентом: Опора не считает их независимым доказательством и не переводит задачу в «готово». Отчёты сохраняются отдельно от настроек и не затирают правки интерфейса.

## Автоматический брендбук

У нового проекта черновик создаётся сразу после подключения папки: палитра из сцен, тем и скриптов, файлы шрифтов, размеры текста, параметры оформления и до шести изображений-кандидатов. Показываются пути и строки источников.

В существующем проекте откройте **Брендбук → Собрать из проекта**. При повторном анализе выбирайте поля для замены: ваши правки по умолчанию сохраняются. Картинки добавляются кандидатами, утверждённые образцы не теряют статус.

Это локальный статический анализ, без отправки игры в нейросеть. Частота цвета в файлах не определяет его роль. Художественное настроение не угадывается, динамический вид запущенных экранов не анализируется. Если явных цветов нет, предлагаются приблизительные цвета выбранных изображений.

## Обновления прямо из программы

**Обновления → Проверить обновления → Скачать обновление → Установить и перезапустить.**

Программа загружает описание версии из этой ветки GitHub, а части архива — из указанного неизменяемого коммита. Проверяет размеры и SHA256 каждой части и всего ZIP. Повреждённый архив не устанавливается. Перед заменой сохраняются данные проекта, прежняя папка приложения переносится в резервную копию. При ошибке замены установщик пытается восстановить её.

Установка предназначена для Windows-сборки в доступной пользователю папке. В браузерном демо и при запуске из исходников она недоступна. Новая версия появляется, когда автор опубликует её в канале; приложение само не создаёт релизы.

После первого запуска можно открывать `Opora-App/Opora-win32-x64/Opora.exe` напрямую. Все остальные файлы рядом с exe нужно сохранить.

Быстро посмотреть интерфейс без приложения: откройте `Opora-demo.html` из скачанного ZIP в браузере. Это только демо, оно не подключает папку игры.

## С чего начать

Запишите пять самых частых замечаний в «Постоянные правила». Добавьте брендбук и изображения, когда будете готовы. Выберите одну небольшую задачу и в разделе «Контекст» обновите файлы проекта, затем скопируйте запрос для Claude Code или Codex.

Opora сохраняет существующие `AGENTS.md` и `CLAUDE.md`, добавляя только свой блок. Перед синхронизацией создаётся резервная копия. Приложение не генерирует графику и пока не оценивает соответствие стилю автоматически.

Полная инструкция и результаты аудита: [OPORA.md](OPORA.md).

## О сборке

Интерфейс, брендбук, настройка MCP и обмен инструментами через дочерний процесс проверены под Linux, включая отображение отчёта в приложении. Загрузка и проверка обновлений тестируются отдельно. Запуск exe, `.cmd`, клиентов Claude/Codex и замена приложения непосредственно в Windows здесь не проверены. Бинарник не подписан сертификатом издателя.

Windows-архив хранится частями в `distribution/windows/`, поскольку GitHub не принимает отдельные Git-файлы больше 100 МБ. Запускатель проверяет SHA256 каждой части и всего собранного ZIP. Отдельно скачивать части не требуется — они уже входят в ZIP ветки.
